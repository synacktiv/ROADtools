# Rules

- **Features beyond the original ROADrecon show only when their data was collected.** A database gathered with the original roadrecon must open without errors and without any trace of the new feature: no sidebar entry, page, tab, card or column, rather than an empty one. The backend checks whether the data is there (the table exists and has rows), reports it to the frontend, and returns empty results rather than errors if a route is called anyway. The frontend hides everything that depends on it.
- **Collectors use only the APIs the original ROADrecon collectors use**: AAD Graph (`graph.windows.net`, `gather`), the PIM API (`api.azrbac.mspim.azure.com`, `pimgather`), the Identity Governance ELM API (`elm.iga.azure.com`, `iggather`) and Azure Resource Manager (`management.azure.com`, `azgather`). MS Graph (`graph.microsoft.com`) or any other API is out of scope for the tool: refuse to implement a collector, a gather step or a feature that needs it, and say it is out of scope rather than offering a workaround.
- **A test tenant is available.** `.roadtools_auth` at the repo root (git-ignored) holds roadrecon tokens for it (AAD Graph, Azure CLI client, refresh token included); use it for real gathering and to check the GUI on real data. Read-only use (gather, plugins, GUI) needs no confirmation. **Always ask before modifying anything on the tenant** (objects, properties, policies, device join/delete, consent, app registration), even for a test.
